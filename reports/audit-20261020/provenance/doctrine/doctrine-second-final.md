## Activated concepts (15)
- **universal-evidence-before-intervention** — An engineering intervention is earned only by evidence capable of establishing the claimed problem and distinguishing the proposed response from no change or a lower-cost response.
- **data-ingest-population-scoping** — A bulk ingest or backfill that discovers its inputs by traversal must scope discovery to exactly the specified input population and validate the enumerated set against expectations before processing, because recursive patterns silently sweep in unintended nested file classes and the over-collection produces no error.
- **implementation-async-ui-state-design** — Asynchronously loading user-facing content must have an explicitly designed state for every phase - reserved stable geometry before load, visible loading empty and error states, and deliberate activation and dismissal semantics - rather than inheriting the platform's incidental default behaviors for the undesigned phases.
- **implementation-attention-budget-presentation** — Output delivered into a consumer's finite attention or context budget - a report, packet, escalation queue, or summary - must be a prioritized, deduplicated, size-bounded presentation view rendered over unchanged canonical data; an unbounded dump of internal state is not a report, and unbudgeted delivery quietly converts the consumer into the system's overflow buffer.
- **implementation-config-reference-validation** — Symbolic cross-references and enum values in hand-authored declarative configuration must be validated against the consuming system's actual schema and defined identifiers, failing fast at load time, never written from memory and assumed correct because the file parses.
- **implementation-rank-before-truncate** — Selecting the top-N most relevant items requires scoring and ordering the entire bounded candidate set before truncating; exiting the scan once N items are collected silently substitutes arrival order for the intended ranking, and match text must be composed only of content fields, never internal classification metadata that queries can spuriously match.
- **operations-symptom-cause-monitoring** — Monitoring answers two distinct questions - what is broken (the symptom) and why (the cause) - and the paging signal must be the user-visible symptom while cause-oriented signals serve diagnosis; coverage means the four golden signals - latency, traffic, errors, saturation - with failure defined by policy and content, not only protocol codes, because a success status wrapping wrong content is still an error.
- **data-dedup-key-identity-completeness** — A uniqueness or deduplication key must include every dimension of the record's true logical identity; an under-scoped key makes two distinct records collide, and when the collision handler is silent suppression - ON CONFLICT DO NOTHING, last-write-wins, ignore-duplicate - under-scoping becomes silent data loss instead of a visible error.
- **operations-external-capability-verification** — An external system's documented or advertised capability - protocol, command language, data format, endpoint behavior, model or version identity - is a claim, not a fact; establish the actual capability from the system's own evidence and verify the integration end-to-end against the real device or endpoint before declaring it working, because a capability mismatch can fail completely silently while every component appears healthy.
- **python-repository-shaped-idiom** — Pythonic form is contextual interoperability with the repository's supported interpreter, dependencies, tooling, neighboring code, and public behavior, not permission for style-only modernization.
- **universal-repository-contract-precedence** — Explicit task authority, accepted repository decisions, executable contracts, and current runtime facts govern the work before any generic engineering school or source preference.
- **universal-separate-semantic-structural-change** — Feature behavior, defect repair, refactoring, architecture, migration, optimization, cleanup, deletion, and dependency changes remain distinct checkpoints even when one task needs several.
- **universal-preserve-behavior-by-default** — Existing observable behavior remains protected unless an accepted contract explicitly identifies what may change and who can accept it.
- **agent-conduct-authority-bounded-action** — Observation, diagnosis, recommendation, selection, execution, verification, and acceptance are distinct authority levels; technical access and sufficient evidence at one level do not grant the next.
- **universal-no-change-option** — Leave code or architecture unchanged when demonstrated pressure and expected benefit do not exceed intervention, migration, indirection, learning, and operational cost.

## Conflicts (3)
- conflict-refactor-now-vs-leave-alone — refactor-opportunistically: Improve nearby structure while understanding is fresh to prevent compounding design decay. vs. leave-stable-code: Avoid regression and opportunity cost where unattractive code is stable or outside the authorized change surface. Selection rule: Refactor only when demonstrated pressure and near-term benefit clear protection, integration, and opportunity costs; otherwise record the signal and revisit trigger without intervention.
- conflict-uniformity-vs-context-sensitive-design — repository-uniformity: Consistency lowers cognitive load, tool cost, and accidental variation. vs. local-fit: Different quality, domain, runtime, or language forces may require intentionally different structures. Selection rule: Conform by default; introduce a documented local exception or migration only when distinct forces produce material benefit exceeding ecosystem and review cost.
- conflict-upfront-vs-evolutionary-architecture — decide-up-front: Resolve high-cost, safety-critical, procurement, data, or topology decisions before implementation makes them expensive or impossible. vs. evolve-from-feedback: Delay reversible decisions and evolve structure through implementation, domain, and runtime feedback. Selection rule: Classify decisions by reversibility, consequence, information value, and decision deadline; decide only the irreversible/high-consequence minimum early and establish feedback plus revisit triggers for the rest.
